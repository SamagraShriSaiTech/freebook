# FreeBooks Core v3.7.0 — SEO, Performance & Launch Handoff

## Architecture rule
The WordPress installation is the CMS at `cms.freebook.co.in` and must remain `noindex,nofollow`. Its WordPress sitemap is intentionally disabled. The public Next.js application at `freebook.co.in` owns all indexable SEO output, canonical URLs, robots.txt, XML sitemap, structured data, analytics tags and public performance work.

## New settings
Open **Settings → FreeBooks settings**:
- Public sitemap URL: `https://freebook.co.in/sitemap.xml`
- GA4 Measurement ID: `G-XXXXXXXXXX`
- Google Search Console verification token
- Bing Webmaster verification token
- Require analytics consent: keep enabled unless your privacy review explicitly approves another setup.

## Public configuration endpoint
`GET /wp-json/freebooks/v1/frontend-config`

This endpoint returns only public integration values. It does not expose the cache revalidation secret. Fetch it server-side from Next.js or copy the values into deployment environment variables. Do not load analytics until the consent manager records valid analytics consent.

## Next.js responsibilities
1. Generate one canonical URL per indexable page.
2. Emit unique title, meta description, Open Graph and Twitter metadata.
3. Emit Organization, WebSite/SearchAction, BreadcrumbList, Book/Product/Offer, Article and FAQPage JSON-LD only where page content supports it. Avoid duplicate schema from multiple SEO systems.
4. Generate `sitemap.xml` from published, indexable public routes. Exclude cart, checkout, account, private portals, internal search and filter combinations.
5. Keep `robots.txt` indexable for the public frontend and point it to the public sitemap. Do not copy the CMS noindex rule to the public domain.
6. Add Google/Bing verification meta tags using the configured tokens.
7. Enforce analytics consent before loading GA4. Support accept, reject and change-preferences controls; persist the choice according to the published privacy policy.
8. Use static generation/ISR and CDN caching for public pages. Keep private account, checkout and donation tracking responses uncached.
9. Use responsive AVIF/WebP images, width/height attributes, lazy loading below the fold, and preload only the primary hero image.
10. Measure Core Web Vitals from real users. Targets at the 75th percentile: LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1.

## Monitoring
Open **FreeBooks → SEO & monitoring** and run checks. Weekly checks are also scheduled through WP-Cron. On low-traffic hosting, configure a server cron and verify it runs. The dashboard is a configuration diagnostic, not an uptime SLA or a substitute for real browser, payment, email, backup-restore and security tests.

## Search engine setup
- Verify the public domain in Google Search Console and Bing Webmaster Tools.
- Submit only `https://freebook.co.in/sitemap.xml`.
- Inspect the homepage, shop/category, book detail, donate, impact and editorial pages.
- Confirm CMS URLs remain excluded/noindex.
- Monitor indexing, crawl errors, Core Web Vitals and manual actions after launch.

## Release validation
Run the full FreeBooks acceptance suite after all modules are installed. This plugin release has PHP syntax and ZIP integrity checks only; it has not been tested on the user's live WordPress/WooCommerce installation.
