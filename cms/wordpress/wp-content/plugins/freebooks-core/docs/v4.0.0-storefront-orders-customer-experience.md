# FreeBooks Core v4.0.0 — Advanced Storefront, Orders & Customer Experience

## New capabilities
- `[freebooks_order_history]` displays a signed-in customer's paginated WooCommerce order history, status filter, line items, totals, order-detail links and repeat-purchase links for currently purchasable, in-stock simple products.
- Repeat purchase uses WooCommerce's cart and rechecks product availability at request time. Variable products and unavailable items are not auto-added.
- Authenticated customer REST endpoints:
  - `GET /wp-json/freebooks/v1/customer/orders?page=1&per_page=10&status=processing`
  - `GET /wp-json/freebooks/v1/customer/orders/{order_id}`
- The order detail endpoint returns only the current logged-in customer's order. The order list is scoped to the current customer.
- REST order details include line items and customer-visible order notes. Billing addresses, payment credentials and private admin notes are not exposed.
- The existing catalogue search, discovery analytics, recommended books, recently viewed, wishlist, back-in-stock request, order lookup, customer account and support workflows are retained.

## Setup
Add `[freebooks_order_history]` to the customer account/orders page if a separate order-history view is desired. WooCommerce My Account remains the primary account and order authority.
The Next.js frontend may call the customer REST endpoints only with a logged-in WordPress/WooCommerce session and valid REST nonce/cookie authentication. Do not expose application secrets in browser code.

## Authority and integration boundaries
- WooCommerce remains authoritative for checkout, orders, payment status, refunds and cart operations.
- Payment gateways remain responsible for payment confirmation and webhook signature verification.
- Shipping carrier plugins remain responsible for shipment booking, parcel tracking and delivery events.
- FreeBooks Core does not store payment credentials or create carrier labels.

## Compatibility and validation
No existing records are deleted or rewritten. No new database tables are created.
PHP lint and ZIP integrity checks do not constitute live WooCommerce checkout, REST authentication, or carrier-plugin acceptance tests. Back up the database and `wp-content` before replacing the installed plugin.
