# FreeBooks Core v4.1.0 — Checkout, Shipping & Fulfilment

## Included
- WooCommerce order fulfilment panel in the order editor (classic order screen and HPOS order screen).
- Staff can record fulfilment status, carrier name, tracking/AWB number, carrier tracking URL, dispatch date and estimated delivery date.
- Optional customer email notification when fulfilment status changes.
- Customer-facing `[freebooks_shipping_status]` shortcode for signed-in customers.
- Adds a Track shipment action to WooCommerce My Account order actions when a tracking URL exists.
- Customer-authenticated REST order responses now include fulfilment status and tracking fields, scoped to the logged-in customer's own orders.
- Admin FreeBooks → Fulfilment overview lists recent WooCommerce orders and recorded fulfilment information.

## Important carrier boundary
This module does not book shipments, buy labels, calculate live carrier rates, generate AWB numbers, or poll carrier tracking APIs. Staff first use the selected carrier plugin (for example, Delhivery/Shiprocket if installed and configured), then copy the tracking details into the FreeBooks order panel. Carrier plugins remain authoritative for shipment booking, tracking scans, labels and delivery events.

## Customer page
Add `[freebooks_shipping_status]` to a customer account or delivery-status page. Customers must sign in to see the shipment details. Existing WooCommerce order detail pages remain available.

## Admin workflow
1. Process and confirm the WooCommerce order/payment as usual.
2. Book the shipment in the carrier plugin.
3. Open the WooCommerce order and enter carrier/tracking details in the FreeBooks fulfilment panel.
4. Select the current fulfilment status and optionally notify the customer.
5. Update status when the carrier confirms delivery or reports an exception.

## Data and safety
- Shipment fields are stored as WooCommerce order metadata; no new database tables are created.
- Payment and refund status remain controlled by WooCommerce and the payment gateway.
- Carrier tracking events are not fabricated or inferred.
- Customer REST routes continue to require authentication and only return the customer's own order.
- Back up database and `wp-content` before replacing the plugin.

## Validation limits
PHP lint and ZIP integrity are static checks. Live testing is still required for WooCommerce classic orders, HPOS, email delivery, customer account access, REST cookie/nonce authentication and the installed carrier extension.
