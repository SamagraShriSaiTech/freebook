# FreeBooks Core v3.9.0 — Donor CRM & Campaigns

## Included
- Donor CRM groups donation history by normalized email address and shows repeat-donor counts, submitted item quantities, latest activity and donation references.
- Donation campaigns use a private WordPress campaign content type under the FreeBooks menu.
- Staff can attribute donations to campaigns from the donation editor. Public REST donation submissions may include a valid `campaign_id`.
- Campaign reports show donation counts, received/listed/sold-stage counts, submitted item quantities and general/unassigned donations.
- Bulk CSV intake accepts up to 500 rows per import (5 MB maximum). Required columns: `name,email,phone,title,category`. Optional columns: `city,quantity,condition,details,handover,campaign_id`.
- Donor preference fields are stored separately from operational status updates: `marketing_opt_in` and `preferred_contact`. Existing donor update emails remain operational and are not marketing campaigns.

## CSV template
`name,email,phone,city,title,category,quantity,condition,details,handover,campaign_id`

Each valid CSV row creates one donation record with one item group and enters the existing donation review workflow. Staff must verify imported records before approval/receiving/listing. Do not import records without a legitimate donor submission/consent basis.

## Admin navigation
FreeBooks → Donor CRM, Campaign reports, Bulk intake, and Donation campaigns.

## Data and privacy
- No existing donation or catalogue records are deleted or rewritten.
- Donor profiles are derived from existing donation metadata; there is no automatic WordPress user-account creation.
- Donor matching uses normalized email address.
- Marketing opt-in is a preference flag only. This release does not send bulk marketing emails.
- CSV exports/imports contain personal data; restrict staff access and store files securely.
- Campaign reports are operational counts, not monetary donation totals or verified student-impact claims.

## Notes
PHP syntax and ZIP integrity checks do not replace live WordPress/WooCommerce testing. Back up the database and `wp-content` before replacing the installed plugin.
